## Frozen layout contract

The plaintext archive root is exactly `.` and contains exactly the manifest-derived private member-name set, including root entries `assets/`, `hashes.json`, `manifest.json`, and `oracle.json`. Before encryption, validate the archive as raw USTAR without normalizing names. Parse only 512-byte headers. Every exact member name is strict UTF-8 of length 1 through 100 bytes; bytes 0:100 are those exact bytes followed by NUL padding, bytes 345:500 are all NUL, and longer names reject. Require mode bytes 100:108 exactly `b'0000600\0'` for files or `b'0000700\0'` for directories; uid bytes 108:116 and gid bytes 116:124 exactly `b'0000000\0'`; size bytes 124:136 exactly eleven lowercase octal digits plus NUL; mtime bytes 136:148 exactly `b'00000000000\0'`; and checksum bytes 148:156 exactly six lowercase octal digits plus NUL plus space. Compute the checksum as the unsigned sum of all 512 header bytes after replacing bytes 148:156 with eight ASCII spaces, and require exact equality.

Require file typeflag byte 156 exactly ASCII `0` and directory typeflag exactly ASCII `5`. Require linkname bytes 157:257, uname bytes 265:297, gname bytes 297:329, devmajor bytes 329:337, devminor bytes 337:345, prefix bytes 345:500, and final bytes 500:512 all NUL. Require magic bytes 257:263 exactly `b'ustar\0'` and version bytes 263:265 exactly `b'00'`. A file payload is exactly its declared size followed by NUL padding to the next 512-byte boundary. A directory has encoded size zero and no payload. Exactly two terminal zero blocks are followed immediately by EOF with no trailing bytes.

Reject `./` normalization, absolute names, backslashes, dot-dot segments, duplicate names, file/directory prefix collisions, a wrapper directory, extra root entries, symlinks, hardlinks, PAX or GNU headers, sparse entries, devices, FIFOs, and unknown types. After complete raw archive validation, read the exact `manifest.json` payload bytes from that validated archive. Require compact sorted-key UTF-8 JSON without a trailing newline, reject duplicate or unknown fields, and enforce the closed Revision 60 manifest schema: root fields `contract`, `entries`, `plan_revision`, and `role`; the contract value `hanonly-r60-holdout-manifest-v1`; revision `60`; role `holdout`; the contract-listed entry fields; and the contract-listed target fields. Derive `entry_ids` in manifest order from `entries[].id` and require exactly `r60-h01` through `r60-h04`.

Derive the exact expected member-name set from `manifest.json`, `oracle.json`, `hashes.json`, every exact `source_relpath`, `clean_reference_relpath`, `erase_source_ink_mask_relpath`, and `residual_source_ink_mask_relpath` asset reference, plus `assets/` and every slash-terminated ancestor directory of those references. The actual raw-header member-name set must equal that derived set exactly. Define both `manifest_sha256` and `private_manifest_commitment_sha256` as SHA-256 of the exact validated `manifest.json` bytes. Compute `member_name_digest_sha256` over the compact canonical sorted JSON array of exact unnormalized UTF-8 names. The array and private archive listing never enter a public receipt.

Open one plaintext archive descriptor and retain its descriptor-held inode, size, and mtime. Validate the complete archive and record its SHA-256 and declared archive byte length. After validation, `lseek` that exact descriptor to offset zero, then stream exactly the declared byte length to age stdin while independently hashing and counting the streamed bytes. Require the streamed SHA-256 and count to equal the prevalidated SHA-256 and size, an immediate EOF after that length, and successful age completion. Then `lseek` the same descriptor to zero, rehash it, and require the same SHA-256 plus unchanged inode, size, and mtime before publishing the layout receipt.

The layout receipt closed schema includes exact `entry_ids`, `manifest_sha256`, `private_manifest_commitment_sha256`, `member_name_digest_sha256`, `plaintext_archive_sha256`, `ciphertext_sha256`, and `layout_validator_sha256`, with `manifest_binding_pass=true`. The public commitment independently binds the same entry IDs, manifest SHA, private-manifest commitment, member-name digest, ciphertext, exact layout-receipt SHA-256, and validator SHA-256. The successor commitment binds all of those values. Preflight cross-validates each exact value among the contract, layout receipt, public commitment, successor commitment, ciphertext, and validator file, including `manifest_sha256 == private_manifest_commitment_sha256`.

The validator is fixed at `scripts/hanonly_tar_layout.py`. Its exact file SHA-256 is pinned by identical `layout_validator_sha256` values in the layout receipt, public commitment, and successor commitment; preflight descriptor-hashes the file and requires equality. No caller-selected validator or validator hash is accepted.

## Closed runtime bundle contract

After extraction, the shared test-only runtime bundle validator accepts Revision 60 only when `manifest.json`, `oracle.json`, and `hashes.json` are compact sorted-key JSON with no trailing newline, no duplicate keys, and no unknown fields. Their contracts are exactly `hanonly-r60-holdout-manifest-v1`, `hanonly-r60-holdout-oracle-v1`, and `hanonly-r60-holdout-hashes-v1`; every revision is `60`, and manifest/oracle/hash bindings must match the exact file bytes. Manifest and oracle entries are ordered exactly `r60-h01` through `r60-h04`. Each oracle entry has exactly `id`, `protected_texts`, and `targets`; its targets have the same cardinality, strict order, and IDs as the corresponding manifest targets. Each protected-text record has exactly `roi`, `source_script_class`, `source_text_sha256`, and `source_text_utf8`.

For each entry, the source path is exactly `assets/source/{entry_id}.{png|jpg|jpeg|webp}`, the clean reference is exactly `assets/clean/{entry_id}.png`, and each target uses `assets/masks/{entry_id}/{target_id}-erase.png` plus `assets/masks/{entry_id}/{target_id}-residual.png`. The hash inventory is closed over exactly those referenced assets. Image records use `decoded_kind=sips-normalized-scanlines-v1` and SHA-256 over that NUL-terminated domain, big-endian width and height, PNG color type, and normalized scanline bytes. Mask records use `decoded_kind=binary-mask-v1` and SHA-256 over the NUL-terminated domain `hanonly-r60-binary-mask-v1`, big-endian width and height, and decoded `0/1` mask bits. Raw hashes are SHA-256 of exact asset bytes.

Source and clean reference must decode to equal dimensions. Revision 60 masks are 8-bit grayscale PNGs whose samples are only `0` or `255`; erase and residual masks decode identically and contain foreground. Target masks do not overlap, their union equals the complete decoded-RGBA Source/Clean pixel delta, and every pixel outside that union is byte-identical after decoding. Each target oracle text is NFC, contains at least one Han scalar, reports the exact Han count and SHA-256, uses script class `han_or_mixed`, and expects `select` with no rejection reason. Each protected-text record is NFC, contains at least one Unicode Latin-script scalar, and every scalar is either Unicode Latin script or printable ASCII `U+0020..U+007E`; controls, newlines, emoji, Han, and other scripts reject. It reports its exact SHA-256 and uses script class `latin_or_ascii`. Protected-text ROIs must equal the manifest `protected_rois` in the same strict order. Pure Latin text cannot be a target and is represented only by these protected ROIs, each disjoint from every target edit ROI.

## Deterministic tests

- A synthetic flat canonical USTAR archive with the exact private member set passes.
- Golden tests compare the complete exact 512-byte regular-file header and complete exact 512-byte directory header byte-for-byte.
- A synthetic archive with one wrapper directory fails.
- Each forbidden raw-member form fails independently: `./` normalization, absolute name, backslash, dot-dot segment, duplicate name, file/directory prefix collision, extra root entry, symlink, hardlink, PAX header, GNU header, sparse entry, device, FIFO, and unknown type.
- Each raw-header invariant fails independently when drifted: 512-byte framing, checksum, magic, version, exact name encoding, member order, uid, gid, uname, gname, mtime, regular-file mode, directory mode, allowed type, declared payload size, zero padding, either terminal zero block, EOF position, or trailing bytes.
- Checksum mutation tests independently reject a checksum computed without the eight-space substitution and any mismatch in the unsigned 512-byte sum.
- Each numeric field's exact digit count, lowercase-octal alphabet, NUL terminator, and remaining padding is mutated independently for mode, uid, gid, size, mtime, and checksum; checksum also independently rejects a wrong final space.
- Name tests independently reject invalid UTF-8, zero length, length over 100 bytes, incorrect NUL padding, and any non-NUL prefix byte.
- Directory tests independently reject nonzero encoded size and any payload byte.
- A regular-file header with typeflag byte 156 mutated away from ASCII `0` fails independently.
- A directory header with typeflag byte 156 mutated away from ASCII `5` fails independently.
- A header with any non-NUL linkname byte in bytes 157:257 fails independently.
- A header with any non-NUL devmajor byte in bytes 329:337 fails independently.
- A header with any non-NUL devminor byte in bytes 337:345 fails independently.
- A header with any non-NUL final-padding byte in bytes 500:512 fails independently.
- A canonical closed `manifest.json` whose references derive the actual exact member set passes and yields `manifest_binding_pass=true`.
- A synthetic Revision 60 runtime bundle with exact manifest/oracle/hashes contracts, IDs, paths, hashes, equal source/clean dimensions, binary grayscale masks, exact Source/Clean delta coverage, and Han target semantics passes through the shared validator.
